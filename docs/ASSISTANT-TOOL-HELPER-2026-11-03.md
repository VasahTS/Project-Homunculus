# Optional Assistant retrieval helper — 2026-11-03

Author: **CODEX**. Status: **local, uncommitted, unpublished on gpt**.
Daniel requested more efficient tool use and explicitly selected an optional auxiliary model with its own connection.

Configure **Assistant → Customize → Assistants → Tool helper (optional)**. Turn it on, explicitly pick a saved connection, optionally choose its model, and set reading calls per consultation. Connections are managed in the existing Settings → Connections page. Existing Assistants stay unchanged/off; old settings and chats remain valid.

The principal receives `consult_library({task})` when enabled. It can delegate focused search/reading, while keeping direct reads and all existing writing tools. The helper receives the task and bounded attached-file names, not the full conversation, images, preset or memory. It uses the selected connection's provider/address/credentials/model/limits through the existing connection service. A missing profile produces an actionable error; its configured fallback is deliberately omitted so an outage cannot silently route retrieval to another model.

The runtime, independently of the helper's instructions, permits only find/read/guide/folders and any enabled file/web reading tools. No create/change/import/move/picture/Trash/memory writes, recursive delegation or approval bypass is possible through this tool. Helper guides do not mark the principal's guides as read. Draft-first and existing disabled-tool switches remain effective. Web search/fetch share the reply's existing limits.

The principal gets a brief: at most 2,000 summary characters, bounded evidence (original tool arguments, labels, errors and available `_read` ranges/cursors), incompleteness warnings, and an explicit statement that this is not full source text. Reports stay under 10,000 characters and preserve valid JSON/source cursors on subsequent user turns. Helper steps remain stored/expandable locally; their full bodies are not replayed to the principal. Both models are instructed to read exact source fields before replacing whole fields; summaries are never automatically used as replacement data.

Bounds: two consultations per reply; default eight tool calls per consultation, configurable 1–20; at most one extra model response after that tool allowance; 4,000-character tasks/tool arguments; repeated exact calls stopped after two executions; bounded helper source/context/results; requested output allowance capped at 2,048 tokens. Stop reaches the active helper and preserves completed trace/usage with a correctly paired stopped parent tool call. Provider failure or an empty brief returns an incomplete result without silently retrying through the main model.

Usage is separate on each reply (`used.helper`: model, model/tool calls, input/output tokens, provider-reported cost, time), visible in the reply footer and local helper step disclosure. Chat and Usage totals include both models. Missing provider usage/cost is not an empirical cost measurement. Delegating avoids replaying raw retrieved pages to the principal; total savings and latency depend on the chosen models and task. No production savings claim is made without live-provider comparison.
